# `results/dchain_null/` — the estimator-artifact falsification

These rows answer a different question from `results/phase2/` and
`results/phase2_residual/`, on **simulated** data, and **must not be pooled with
either**. Phase 2R asks "can anything predict `D_res` for an unseen pair of the
Koplev screen"; this asks "does the estimator that produced the Koplev screen
produce the same answer when the true pair-specific interaction is zero".

Every row here is a simulation. No row is a measurement of a real screen. The
only real numbers that appear are the fixed reference values quoted from
`results/phase2_residual/summary/`, and they are never recomputed here.

| file | what it is |
|---|---|
| `metrics.jsonl` | one row per simulated screen: config, both seeds, estimator diagnostics, the true and estimated decompositions, and the Phase 2R rows run on it |
| `configs/*.json` | the exact condition list each `--part` ran, written before the part starts |
| `summary/` | regenerated by `scripts/report_dchain_null.py` |
| `summary/detection_curve.json` | how large a rank-2 artifact must be before the primary detector sees it. Measured after the primary block, because "the null shows no skill" is a statement about the world only to the extent the detector would have seen skill had it been there |
| `simulations/` | **gitignored.** Simulated wells and raw MCMC output, tens of MB per seed; regenerated by `scripts/run_dchain_null.py` |

## Blocks

| tag | what | preregistered size |
|---|---|---:|
| `primary` | NULL-A (true pair interaction exactly zero) through the published sampler | 20 |
| `realism` | NULL-B (independent combination nuisance, still no reusable pair structure). **Raised from 10 to 20 after review: this is the arm where the artifact is larger, not smaller** | 20 |
| `oracle_strict`, `oracle_nuisance` | **Control A** — the synergy measure at the *true* parameters. Must not show the signature, or the null is malformed | 20 + 20 |
| `unshared` | **Control C** — the same estimation problem with parameter sharing removed | 20 |
| `noise_sd0.075`, `noise_sd0.3` | **Control D** — the preregistered noise sweep | 6 each |
| `convergence` | four MCMC chains on one dataset, to size the MCMC error in the target | 4 |

**Control B** is not a block: it is computed inside every row as
`artifact = estimate − truth`, with its own decomposition.

## Reproduction

```
python scripts/download_koplev.py         # once, for the real reference values
python scripts/prepare_dchain_null.py     # once, ~10 s: fetch, patch, build, verify
python scripts/run_dchain_null.py --counts
python scripts/run_dchain_null.py --part oracle     # Control A, seconds
python scripts/run_dchain_null.py --part unshared   # Control C, ~5 min
python scripts/run_dchain_null.py --part primary    # the experiment, hours
python scripts/report_dchain_null.py
```

The `joint` parts run `dchain.cpp` at its own compiled-in defaults — 500,000
iterations, 1,999 retained samples, the settings the deposit is provably at —
which is roughly 100 minutes per simulated screen on one core.

The pre-registration is in `docs/PREREGISTRATIONS.md` and was committed before any
joint-estimator run. The analysis is
[`docs/dchain_null_falsification.md`](../../docs/dchain_null_falsification.md)
and the source reconstruction it rests on is
[`docs/dchain_reconstruction.md`](../../docs/dchain_reconstruction.md).
